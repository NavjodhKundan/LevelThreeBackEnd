# 3.2 — Understand and document the Supabase config

**Labels:** chore, database, day-3

## Branch
Before starting, create your branch:
```
git checkout -b understand-supabase-config
```

## Description
You've been using `src/config/supabaseClient.js` and a `.env` file since Day 2 without necessarily knowing how they work. Now that class has covered environment variables and the Supabase client setup, confirm you understand your own project's config by documenting it and making sure it's set up correctly and securely.

## Acceptance Criteria
- [ ] Your own `.env` file exists locally (copied from `.env.example`) with your real `SUPABASE_URL` and `SUPABASE_KEY`, and is not committed to git
- [ ] You can explain, in a comment or short note, what `supabaseClient.js` does line by line
- [ ] `.env` is confirmed present in `.gitignore`
- [ ] All Day 2 routes still work after you've reviewed/re-verified the config (no functional change required — this is a checkpoint, not a rebuild)

## Submit
When your acceptance criteria are all checked off:
```
git add .
git commit -m "your message here"
git push origin understand-supabase-config
```
Your commit message should summarize what you actually changed (not just "done" or "fix") — write it like you're telling a teammate what this branch does.

Then open a Pull Request on your own fork's GitHub page (base: your `main`, compare: your branch) and add **your-instructor-github-username** as a reviewer.
